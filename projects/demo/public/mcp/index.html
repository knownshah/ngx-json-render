ngx-json-render MCP App

An MCP server with one tool, render-ui. When you ask your AI assistant for a dashboard, a form, a status summary or a comparison, it describes the UI as a json-render spec and the tool renders it inline in the chat as interactive Angular Material components: tables, cards, metrics, forms with validation, tabs, lists and buttons.

It works in any client that supports MCP Apps: Claude, ChatGPT, VS Code, Cursor, Goose and others. No account and no authentication are needed, and the server stores nothing (see the privacy policy).

Connect

Server URL (Streamable HTTP, no authentication):

https://ngx-json-render.vercel.app/mcp
  • Claude: Settings → Connectors → Add custom connector, paste the URL.
  • Claude Code: add the server from a terminal. Without -s user it is added to the current project only. 
    claude mcp add -s user --transport http ngx-json-render-ui https://ngx-json-render.vercel.app/mcp
    claude mcp get ngx-json-render-ui should report Connected; the render-ui tool is available in sessions started after that.
  • ChatGPT: Settings → Apps → Advanced settings → Developer mode, then create an app with the URL.
  • VS Code, Cursor: add it to your MCP configuration: 
    {
  "mcpServers": {
    "ngx-json-render": { "url": "https://ngx-json-render.vercel.app/mcp" }
  }
}

Examples

The render-ui tool

  • Input: spec, a json-render spec: a root element key, a flat map of elements (each a component type, its props and its children), and an optional state object that props bind to. The tool description lists the 28 available components and their props.
  • Output: the same spec, which the app's view renders. A spec that names an unknown component or passes invalid props is rejected with an error describing what is wrong, so the model can fix it.
  • Read-only: the tool reads and changes nothing outside the chat. Buttons and form fields change the view's own state only.

Limitations

  • The UI shows data the model already has in the conversation; the server does not connect to your systems or fetch data.
  • Buttons act inside the rendered view (update fields, validate a form) and do not send data anywhere.
